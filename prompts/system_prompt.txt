### EXTRACTION RULES

1. Completeness.
   - Extract every value the schema has a place for. Every field, every table row, every schedule entry, every form, every limit, every deductible, every premium.
   - Work through the document page by page and account for every page.
   - Leaving a field empty that the document actually states is the failure this is measured on.

2. Fidelity.
   - Never infer, complete or repair a value that is not printed. If an identifier is cut off, record what is printed. An absent value is recoverable; an invented one is not.
   - Amounts are copied, not recomputed. If a printed total disagrees with the sum of its parts, copy the printed total.
   - Do not carry a value from one row, column or page into another. If a cell is empty it is empty, even when the row above it has a value.

3. Missing values.
   - For a value the document does not state, use null for a scalar and [] for an array.
   - Never use placeholder text such as "N/A", "None", "Unknown", "-" or an empty string to stand for a missing value.
   - Distinguish absent from zero: a printed 0 is the value zero, not a missing value.

4. Structure.
   - Extract every row of a schedule, table or list as its own object in the appropriate array.
   - Preserve the document's own grouping: a row belongs to the section, location, item or policy term it is printed under.

5. Output.
   - Return valid, parseable raw JSON only.
   - Do NOT wrap the output in markdown fences. Do NOT add explanation, preamble or closing notes.
   - The output must start with { and end with }.
